# OpenClash 维护指引

先读 [入口](README.md)、[部署状态](../docs/deployment-status.md) 与 [覆写接入](overrides/README.md)。本页是方法，不是执行设备变更或发布的额外授权。

## 检查真实所有者

1. 核实目标网关和授权范围；读取实际 UCI 与激活源，不从示意角色或旧名字推断 IP。
2. 核对转换器位置：同机调用可用 127.0.0.1:25500，跨机器调用必须使用真实后端地址；不能盲目填回环。
3. 区分完整转换 URL 和原始订阅加在线转换设置。只有前者避免再次转换；不预设所有订阅必须开启或关闭某个开关。
4. 检查实际镜像、版本、协议与过滤结果；模板路径、UA、分组与规则数以实际源为准。
5. 读取自定义规则与 overwrite hook，确认个人节点源、AI 规则和 store-selected 的生成路径。

## 修改范围

- 节点地址变化：仅更新对应持久节点及受影响运行配置，保留其他协议字段和选择；备份后校验、加载和读回。
- 订阅更新：按每个源分别检查成功、失败或保留旧配置；聚合成功不等于全部源成功。
- 规则/分组：在正确的生成层注入，保留其他配置；不要为加一条规则替换整个 rules 数组。
- 不同网关不强行统一内核、DNS、认证或网络；这不是已验收的自动切换集群。

## 验证与记录

检查持久源、生成 YAML、内核控制接口、组当前选择与有限真实请求。节点 delay、HTTP 首页、配置校验各自只证明该层；没有付费推理、端到端终端或故障切换证据时明确标注。

部署前备份；失败时恢复源与原运行配置，按实际版本加载并恢复选择。只恢复生成 YAML 可能在下一次重建再次被覆盖。完整方法见 [覆写说明](overrides/README.md)。真实凭据与备份不进入 Git，日志不输出节点认证或订阅 URL。

设备写入、刷新订阅、重启服务、commit/push 均遵循用户当次授权；仓库变更不会自动部署。当前设备状态与匿名事件记录维护在 私有知识库。
