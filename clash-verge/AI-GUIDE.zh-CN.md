# Mac 代理维护指引

本页说明仓库的配置分层，不把文档中的历史部署当作当前事实，也不扩大用户授权。读取 [Mac 入口](README.md) 与 [部署状态](../docs/deployment-status.md)，再核对目标版本、激活订阅和实际文件。

## 先确认范围

区分修改仓库模板、读取本机、部署到设备、切换选择和 Git 发布。一次文档更新不代表已经部署。已有授权范围内连续完成；设备写入、订阅刷新、服务重启与发布按用户实际授权执行。

## 真实配置入口

- 规则及个人节点：Verge profiles/Script.js；合并仓库 shared/Script.js 的公共逻辑，保留本机 customNodes/customRules。
- DNS：先确认本机选择的持久源；dns_config.yaml 是一种可选来源，见 [DNS](docs/dns.md)；shared/Merge.yaml 不包含 DNS。
- 订阅：核对原始订阅或转换器 URL、激活 profile、UA 及专属扩展。存在 Compose 模板不代表本机容器已运行。
- 生成 YAML 与 socket 控制接口：读取最终节点、分组、规则及选择，不以文件保存成功替代验收。

## 按问题处理

| 问题 | 最小检查与修改 |
|---|---|
| 缺节点或协议 | 对比原始源和转换结果，区分拉取失败、过滤与解析支持，不预设某镜像永远全协议支持 |
| 个人节点消失 | 检查本机 customNodes、allowlist 和订阅扩展顺序；保留其他节点与协议字段 |
| AI 组不存在 | 检查兼容组映射，避免循环引用或静默 DIRECT；选择出口须有明确依据 |
| 私网/组织域名失败 | 核对 DNS 策略、Fake-IP 排除和实际 VPN/路由；真实域名不写入仓库 |
| 规则不生效 | 查生成结果及真实命中；本机进程规则不能照搬为客户端的路由层规则 |

## 最小验收

修改前备份与差异检查；修改后核对持久源、生成结果、选择和受影响请求。节点数量与规则数量不固定，节点 probe 不是 AI 推理验收。恢复原配置后同样要读回并检查业务。

仓库离线检查命令见 [根 README](../README.md)。没有修改或验证设备时，不更新其 Last verified 日期。
